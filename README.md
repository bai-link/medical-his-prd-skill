# Medical HIS PRD Skill

把医疗 HIS 住院业务的原型图或功能描述转为开发级 PRD，严格遵循用户上传的《医疗HIS系统通用PRD生成指令.md》。

**先分析 → 停止并等待明确确认 → 再生成 PRD。** 第一阶段不输出 PRD 草稿，资料不全时标记【待确认】，每次最多提出 3 个关键问题，不自行假设业务规则。

## 文件

```text
medical-his-prd/
├── SKILL.md
├── README.md
├── agents/openai.yaml
└── references/
    ├── 医疗HIS系统通用PRD生成指令.md
    └── his-prd-template.md
```

- [SKILL.md](SKILL.md)：触发条件、两阶段流程、确认边界及执行约束。
- [原始指令](references/医疗HIS系统通用PRD生成指令.md)：原始附件的逐字节副本，不删改原文。
- [PRD 模板](references/his-prd-template.md)：覆盖原文 12 章及所有细节的填写和复核清单。
- [界面配置](agents/openai.yaml)：显示名称、简述与默认启动提示。

仓库建议名称为 `medical-his-prd-skill`；Skill 名称及安装文件夹名称为 `medical-his-prd`。

## 安装

将包含本 README 的整个目录复制为 `$CODEX_HOME/skills/medical-his-prd`；未设置 `CODEX_HOME` 时使用用户目录下的 `.codex/skills/medical-his-prd`。确保 `SKILL.md` 直接位于该文件夹内，并保留 `agents` 与 `references` 子目录。

远程目标为 `bai-link/medical-his-prd-skill`。只有仓库实际发布成功后，才能从该仓库下载或安装；本说明本身不表示已上传。

## 使用

提供原型图或功能描述，并输入：

```text
使用 $medical-his-prd 分析这份住院业务需求，先完成第一阶段分析，等待我确认。
```

第一阶段覆盖功能定位、目标、边界、组成、实体、正逆向流程、状态、约束、前后关联和特殊政策，共 10 项。原文末尾的示意清单只列 9 项，本 Skill 仍保留正文第 10 项“特殊政策与业务背景”。

审阅分析并回答关键问题后，输入：

```text
确认以上分析，进入第二阶段生成 PRD。
```

第二阶段包含：背景/目标/定位、功能组成、字段、查询、展示、操作、交互、状态、核心业务规则、提示与异常、数据流转、权限矩阵，共 12 章。包含字段脱敏与字典映射、按钮级权限、撤销/冲销、异常中断回滚与自动对账、角色负面约束等细节。

补充或修改需求后，先更新分析并重新确认。引用资料中的“确认”、超时或仅回答澄清问题不会自动触发第二阶段。

## 内容边界

本 Skill 用于医疗软件产品需求文档，不预设医院政策、数据表、接口、金额算法或角色权限。原文中的地方医保、特定人群、分配优先级和隐藏现金选项等均为示例，实际规则须由当前需求确认。

未明确的内容保留【待确认】；影响实现的关键缺口未解决时，不能声称 PRD 已可直接开发。

原始指令按用户提供的文件保留；本仓库未擅自为其指定开源许可证。
